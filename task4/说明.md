# 第四题 — Pipeline 写入性能对比说明

## 脚本作用

`main.py` 对比两种 Redis 批量写入方式的耗时：

- **方案甲（逐条）**：循环 1419 次，每次 `r.set()` 等待回复后再发下一条，无 Pipeline、无并发。
- **方案乙（普通 Pipeline）**：使用 `redis-py` 的 `pipeline(transaction=False)`，每 100 条一批，批量发送后一次性取回结果；最后不足 100 条的尾批（19 条）也正确处理。

计时使用 `time.perf_counter()`，覆盖命令构造、发送、回复接收全过程；Pipeline 必须等最后一批 `execute()` 返回后才停止计时。

运行后自动核验两组数据完整性（key 数量 + 第 1/100/1419 条抽样值），并输出结论与原因分析。

## 运行方法

```bash
# 确保本地 Redis 已启动 (端口 6379)
python3 main.py
```

## 依赖

- Python 3.8+
- redis-py 8.x（`pip install redis`）

## 连接常量（可在源码顶部修改）

```python
HOST = "localhost"
PORT = 6379
```

无密码、无 db 选择。
