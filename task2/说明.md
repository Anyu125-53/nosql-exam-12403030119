# 第二题说明（MongoDB 原子扣减与事务验证）

## 文件构成
- `init.py`：初始化脚本，可独立运行。连接 `exam_12403030119`，
  清空 `inventory`、`orders` 两个集合，并插入库存文档
  `_id=BOOK-12403030119`、title="NoSQL数据库教材"、stock=Stock=9。
- `main.py`：业务与测试代码。**不调用 init.py**；每个测试场景开始前
  由 `reset(db, stock)` 单独重置两个集合，场景之间互不影响。核心要点：
  1. **原子扣减**：`purchase()` 内用单条
     `update_one({"_id":BOOK_ID, "stock":{"$gte":BUY}}, {"$inc":{"stock":-BUY}})`，
     把“库存条件检查”与“扣减”合并为一次服务端原子操作，
     不采用“先查询、再无条件扣减”。
  2. **结果三分类**：依据 updateOne 返回的 matchedCount/modifiedCount 与异常区分——
     扣减成功（commit 后返回 SUCCESS）；matchedCount=0 时在同一事务内读一次
     库存文档，区分“教材不存在(BOOK_NOT_FOUND)”与“库存不足(INSUFFICIENT_STOCK)”；
     其余异常统一为 DB_ERROR。扣减失败绝不插入订单。
  3. **事务**：扣减与订单插入使用同一 `session`、同一 `start_transaction()`；
     `force_error=False` 正常扣减→插订单→commit；`force_error=True` 在扣减成功后、
     插单前主动抛异常，触发 `abort_transaction()` 回滚。
     只有事务 commit 成功才返回订购成功。
  4. **四场景**：T1 正常订购、T2 库存不足（初始 Buy-1=1）、T3 中途异常、
     T4 连续 floor(9/2)+1=5 次；预期值在代码 `EXPECT` 常量中断言，
     并与 `result.txt` 完全一致。
- `result.txt`：四场景预期结果表 + 两道解释题书面答案
  （① 为何仍需事务；② forceError 验证了什么）。
  所有实测耗时/结果均标注“预期/待真机核验”。

## 运行方法
```bash
python3 init.py      # 先初始化（仅执行一次即可）
python3 main.py      # 运行四场景测试并自动比对预期值
```

## 依赖与环境注意
- 依赖：`pymongo`（本机为 4.19.0）。
- 连接常量写在脚本顶部：`HOST="localhost"`、`PORT=27017`、
  `DB_NAME="exam_12403030119"`；源码不含任何账号/密码凭据。
- **重要**：本脚本使用多文档事务（session.start_transaction / commit / abort），
  通常需要**副本集（replica set）环境**；单机 standalone 的 mongod
  **不支持事务**，会报错。真机核验时请在本地副本集或 MongoDB Atlas 等
  集群环境下运行。
